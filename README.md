# 잔고 캘린더 (tide-over)

가용돈이 빠듯한 사람이, 통장 잔고 하나와 앞으로의 예정 수입·지출을 넣고,
"다음 입금까지 이 돈으로"를 확인하는 웹앱.

## 핵심 모델

**입력의 원자는 지출이 아니라 잔고다. 미래는 달력에, 과거는 잔고에.**

- 과거 지출은 입력하지 않는다. 통장 잔고를 옮겨 적는 순간, 그 사이의 모든 변동 지출이
  자동으로 정산된 것으로 본다.
- 달력에는 오늘 이후의 예정 입금·출금만 존재한다.
- 경계는 항상 오늘이다. 오늘 이전 = 잔고가 말함, 오늘 이후 = 달력이 말함.
- 이 앱은 예측하지 않는다. 표시하는 숫자는 "예상 잔고"가 아니라 "이 날까지 쓸 수 있는
  한도"다. 변동 지출을 추정하지 않는 것은 누락이 아니라 정의다.

## 예정 항목

수입과 지출을 같은 모양으로 다룬다. 반복 방식은 세 가지다.

```ts
type Entry = {
  id: string;
  name: string;
  amount: number;              // 항상 양수. 방향은 kind가 정한다.
  kind: 'income' | 'expense';
  schedule:
    | { type: 'once'; date: string }                    // 특정 일자 한 번
    | { type: 'monthly'; day: number }                  // 매달 며칠 (없는 날짜면 말일)
    | { type: 'every'; days: number; anchor: string };  // anchor부터 N일마다 (1주=7)
};
```

급여일 설정은 따로 없다. **급여도 그냥 예정 입금이다.** 온보딩에서 받은 급여일은
'급여'라는 매달 반복 입금으로 저장되고, 설정에서 다른 항목처럼 고친다.

달력에서 날짜를 누르면 **팝업**이 뜬다. 그 날 잡혀 있는 예정을 보여주고, 같은 창에서 새로
넣는다. 날짜는 누른 셀로 채워져 있고 팝업 안에서 고칠 수 있다. 설정의 "+ 예정 추가"도 같은
팝업을 연다 — 만드는 경로는 하나다.

**한 번짜리 예정은 내일 날짜부터만 넣을 수 있다.** 오늘까지는 잔고가 이미 말해주고 있어서,
오늘 날짜에 넣으면 잔고와 이중으로 세어진다. 매달·N일마다 반복은 시작일이 과거여도 된다 —
앞으로의 발생분만 계산에 잡힌다.

## 계산

전부 `src/lib/calc.ts`에 있다.

```
limit(d)  = 현재 잔고 + (오늘 이후 ~ d일까지의 예정 입금 − 예정 출금)
머리 숫자 = limit(끝점)
정산 diff = 새로 적은 잔고 − (직전 잔고 + 그 사이 지나간 예정 입금 − 예정 출금)
끝점      = 다음 예정 입금 전날. 예정 입금이 없으면 30일 뒤 (horizonOf)
```

구간 규칙은 한 가지로 통일돼 있다: **시작은 열려 있고 끝은 닫혀 있다** — `(after, through]`.
그래서 `limit`이 앞으로 반영하는 금액과 `정산 diff`가 뒤로 반영하는 금액이 정확히 맞물리고,
같은 항목이 두 번 세지거나 빠지지 않는다. 오늘 날짜에 잡힌 예정은 이미 잔고에 반영된 것으로
본다.

예정 입금은 한도를 **늘린다**. 아직 안 들어온 돈이 한도에 들어간다는 뜻이므로, 확실한 것만
넣어야 한다.

## 저장

서버도, 계정도, 자동 동기화도 없다. 데이터는 이 브라우저에만 있다.

- **localStorage + 스키마 버전 키** — `tideover.state`에 상태, `tideover.schema`에 버전.
  버전이 올라가면 `src/lib/storage.ts`의 `MIGRATIONS`에 변환을 한 줄 추가한다.
  옛 데이터는 읽는 즉시 올려서 다시 써두고, 앞으로의 버전이 남긴 데이터는 읽지 않고
  경고만 띄운다(덮어쓰지 않는다). **백업 링크도 같은 변환 경로를 탄다** — v1 때 만들어 둔
  링크가 그대로 열려야 하기 때문이다.
- **`navigator.storage.persist()`** — 앱 시작 시 요청한다. 거절당하거나 지원하지 않아도
  앱은 그대로 동작하고, 설정 화면에 상태만 보여준다.
- **백업 링크** — 상태 전체를 base64url로 인코딩해 URL 해시(`#b=…`)에 담는다.
  설정 화면의 "백업 링크 복사" 버튼으로 만든다. 그 링크를 열면 상태가 복원되고,
  기존 데이터가 있으면 **덮어쓰기 전에 확인**을 받는다. 앱이 이미 열려 있는 상태에서
  주소창에 붙여넣는 경우(해시만 바뀌는 같은-문서 이동)도 `hashchange`로 처리한다.
- **지워짐 안내** — 백업 링크를 만들면 이력을 localStorage와 쿠키 양쪽에 남긴다.
  이력 자체가 localStorage에만 있으면 데이터와 같이 날아가서 아무 소용이 없기 때문이다.
  저장된 데이터는 없는데 이력이 남아 있으면 첫 화면에서
  "이전 데이터가 지워졌습니다. 백업 링크가 있으면 열어주세요"를 띄운다.

## 화면

화면은 **달력**과 **설정** 둘뿐이다. 나머지는 전부 팝업으로 연다.

- **달력** — 머리 숫자(끝점까지의 한도), 월 달력, 남은 예정 목록.
  - 날짜 칸에는 그 날의 **개별 내역이 모두** 이름·금액으로 나온다. 칸 높이는 내용에 맞춰
    늘어난다.
  - **오늘부터 끝점까지가 색 띠로 이어진다.** 가로 간격을 없애서 한 줄 안에서는 실제로
    붙어 보이고, 띠의 시작과 끝만 둥글다. 별도 마커나 범례 칩은 쓰지 않는다.
  - **좌우로 밀면 달이 넘어간다.** 55px 이상, 세로 움직임의 1.5배 이상일 때만 넘기고,
    그 경우 셀 클릭은 삼킨다.
- **잔고 다시 적기(팝업)** — 머리 숫자나 "통장 잔고" 값을 누르면 열린다. 직전 잔고 →
  지나간 예정 입금·출금 → 예정대로였다면 얼마여야 하는지를 보여주고, 차이를
  "예정에 없던 지출 −124,000원" 형태로 표시한다. 전에는 별도 탭이었다.
- **설정** — 예정 수입·지출 목록(행에서 바로 수정), 백업·복원, 저장소 상태, 초기화.
  새로 만들 때는 달력과 같은 팝업(`EntryDialog`)을 연다. 급여일 카드는 없다 — 급여는 목록의
  입금 항목이다.

## 개발

```bash
npm install
npm run dev        # 개발 서버
npm test           # 계산·백업·날짜 단위 테스트
npm run typecheck
npm run build      # dist/ 로 정적 빌드 (상대 경로라 어느 하위 경로에도 올릴 수 있다)
```

## 배포

정적 파일뿐이라 아무 정적 호스트에나 올라간다. `vite.config.ts`의 `base: './'` 덕분에
루트든 하위 경로든 그대로 동작한다.

| 호스트 | 설정 |
| --- | --- |
| Cloudflare Pages | 빌드 `npm run build`, 출력 `dist`. 헤더는 `public/_headers`가 자동 적용된다. |
| Vercel | 저장소만 연결하면 `vercel.json`이 빌드·헤더를 다 잡는다. |

- Node 버전은 `.nvmrc`(22)로 고정한다. Vite 7이 Node 20.19+를 요구하는데, 호스트 기본값이
  더 낮으면 빌드가 깨진다.
- `_headers` / `vercel.json`은 같은 내용의 CSP·캐시 정책을 각 호스트 문법으로 적어둔 것이다.
  외부 리소스를 하나도 쓰지 않아서 `default-src 'self'`로 잠가도 그대로 돌아간다.
  `Referrer-Policy: no-referrer`는 백업 링크(해시에 상태 전체가 들어 있다)가 referrer로
  새어 나가지 않게 하려는 것이다.
- 배포 URL은 처음에 정해두는 게 좋다. 백업 링크가 생성 당시의 주소를 담기 때문이다.
  도메인이 바뀌어도 링크를 **설정 → 백업 링크로 복원**에 붙여넣으면 살아나지만, 그냥
  클릭해서 열리지는 않는다.
